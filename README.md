# Sveden Checker

Sveden Checker — локальное веб-приложение для предварительной проверки раздела «Сведения об образовательной организации» на сайте образовательной организации.

Приложение запускается на компьютере пользователя, открывается в браузере и выполняет проверки локально. Проверяемый сайт, HTML-страницы и результаты анализа не отправляются на внешний сервер.

> Sveden Checker не является официальной АИС «Мониторинг», не связан с Рособрнадзором и не заменяет официальную проверку.

## Стек

- TypeScript
- Node.js
- Fastify
- React + Vite
- SQLite
- pnpm workspaces

## Запуск

```bash
pnpm install
pnpm dev
```

Если `pnpm` не установлен глобально, можно использовать совместимую версию через `npx`:

```bash
npx pnpm@9.15.9 install
npx pnpm@9.15.9 dev
```

По умолчанию:

- frontend: `http://127.0.0.1:5173`
- backend API: `http://127.0.0.1:3001`

## Windows release

Portable-сборка для Windows x64 создается командой:

```bash
pnpm release:win
```

Готовый архив появляется в:

```text
release/sveden-checker-<version>-win-x64.zip
```

Архив включает Windows Node.js runtime, собранный frontend, bundled backend, нормативные документы и production-зависимости, включая native-модуль SQLite. После распаковки пользователь запускает:

```text
start-sveden-checker.cmd
```

Приложение открывается в браузере на `http://127.0.0.1:5173`.

## База данных

SQLite-база создается автоматически при первом запуске backend или команды:

```bash
pnpm db:init
```

Файл базы лежит здесь:

```text
packages/database/data/sveden-checker.sqlite
```

Можно переопределить путь переменной окружения `SVEDEN_CHECKER_DB`.

## Нормативные документы

Документы из архива `sveden_legal_documents.zip` распакованы в:

```text
legal-documents/
```

Сохранены исходные PDF/MD-файлы, `legal-sources.json`, `source_urls.md` и `checksums.sha256`.

При первом запуске база заполняет таблицу `legal_sources` из `legal-documents/legal-sources.json`. Если в метаданных нет отдельных полей, приложение аккуратно выводит номер, дату, тип и краткое название из заголовка документа.

Нормативные документы можно открывать прямо из интерфейса. Backend отдает только файлы из локальной папки `legal-documents/` по безопасному endpoint и не предоставляет доступ к произвольным файлам компьютера.

## Рейтинг сайтов

Страница `/rating` запускает массовую локальную проверку сайтов из списка:

```text
site-lists/obr-sites.txt
```

В списке 1356 сайтов. Результаты сохраняются в SQLite после проверки каждого сайта, поэтому приложение можно закрыть или поставить на паузу, а затем продолжить с первого незавершенного адреса. Каждый запуск рейтинга имеет дату создания, статус, прогресс, средний балл и отдельные результаты по сайтам.

На странице рейтинга можно:

- выбрать встроенный или импортированный список сайтов;
- импортировать новый список из текста, по одному адресу в строке;
- настроить количество параллельных проверок, повторы, таймауты, число `addRef`-страниц и глубину проверки документов;
- поставить проверку на паузу с отменой текущих запросов;
- открыть подробный отчёт по конкретному сайту;
- увидеть ETA, распределение баллов, частые недочёты и частые ошибки;
- проверить наличие новой версии на GitHub Releases.

Если у пользователя нет подключения к интернету, массовая проверка останавливается со статусом `offline`, текущий сайт помечается как `no_internet` и не попадает в проверенные. После восстановления соединения запуск можно продолжить.

Для технической проверки этого сценария можно запустить backend с `SVEDEN_CHECKER_FORCE_OFFLINE=1`.

Массовый режим по умолчанию использует ускоренную проверку страниц и `itemprop`: backend проверяет наличие ссылок в HTML, но не выполняет глубокую загрузку каждого документа. Глубокую проверку открытия документов можно включить в настройках рейтинга. Для детальной проверки конкретного сайта также используется страница `/check`.

## Отчеты

Будущие отчеты проверок будут храниться в:

```text
reports/
```

В первой версии checker выполняет локальную HTML-проверку доступности страниц `/sveden/`, обязательных `itemprop`, дополнительных страниц `addRef` и ссылок на документы по расширенному JSON-ruleset.

## API

### `GET /api/health`

Возвращает статус backend:

```json
{
  "status": "ok",
  "app": "sveden-checker"
}
```

### `GET /api/project-info`

Возвращает сведения о проекте, предупреждение о неофициальном статусе, принцип работы, осторожную инструкцию по подключению к АИС «Мониторинг» и список нормативных источников из SQLite.

### `GET /api/legal-sources`

Возвращает список документов из таблицы `legal_sources`.

### `GET /api/legal-sources/:id/file`

Открывает локальный файл нормативного документа из `legal-documents/`, если у источника заполнено поле `local_file`.

### `POST /api/check`

Запускает локальную проверку сайта. Frontend обращается только к этому endpoint, а внешние HTTP-запросы к проверяемому сайту выполняет backend.

Принимает:

```json
{
  "url": "https://example.ru"
}
```

Возвращает:

```json
{
  "siteUrl": "https://example.ru",
  "checkedAt": "2026-05-29T00:00:00.000Z",
  "overallScore": 72,
  "summary": {
    "total": 150,
    "found": 24,
    "partial": 1,
    "missing": 9,
    "errors": 0
  },
  "sections": []
}
```

Расширенный ruleset лежит в:

```text
packages/rulesets/src/sveden-itemprop-ruleset.json
```

### `GET /api/rating-runs/latest`

Возвращает последний запуск массового рейтинга, прогресс и результаты сайтов.

### `GET /api/site-lists`

Возвращает сохранённые списки сайтов.

### `POST /api/site-lists`

Импортирует новый список сайтов из текста.

### `POST /api/rating-runs/start`

Запускает или продолжает массовую проверку. Если передать `{"reset": true}`, создаёт новый запуск с текущей датой. Можно передать `siteListId` и настройки `settings`.

### `POST /api/rating-runs/pause`

Ставит массовую проверку на паузу. Уже начатый сайт может завершиться и сохраниться, после чего следующий запуск продолжит очередь.

### `GET /api/rating-runs/:id`

Возвращает конкретный запуск рейтинга и его результаты.

### `GET /api/rating-results/:id/report`

Возвращает подробный JSON-отчёт по конкретному сайту из рейтинга.

### `GET /api/updates/check`

Проверяет последнюю опубликованную версию в GitHub Releases и возвращает ссылку на Windows exe, если доступна новая версия.

## Рекомендации по исправлениям

После проверки сайта на странице `/check` приложение сохраняет последний отчет в `localStorage` с ключом `sveden_checker_last_report`. На странице `/recommendations` из этого отчета формируются рекомендации по пунктам со статусами `missing`, `partial`, `empty` и `error`.

Рекомендации показывают раздел, URL страницы, проблемный `itemprop`, статус, приоритет, объяснение проблемы, способ исправления и пример HTML-разметки. Для примеров доступна кнопка копирования.

В рекомендациях и в списке найденных недочетов показывается нормативное основание: документ, конкретизированный пункт ruleset для раздела и `itemprop`, ссылка на локальный файл документа и, если есть, ссылка на официальный источник.

Приоритеты рассчитываются автоматически: ошибки загрузки и обязательные отсутствующие пункты попадают в срочные, пустые и частично заполненные значения — в желательные, остальные предупреждения — в низкий приоритет.

Рекомендации являются справочными и не заменяют официальную проверку в АИС «Мониторинг».
